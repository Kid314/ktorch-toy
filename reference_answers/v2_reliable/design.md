# v2 设计说明：从可运行到可恢复

## 版本问题

v1 的主要边界是“每次从头训练，看到 loss 和生成”。它适合学习前向和反向，但实验一旦中断，不能知道是否已经用过哪些随机窗口、AdamW 的矩状态是什么、checkpoint 是否被截断。v2 专门解决这些可靠性问题，保持模型主体稳定以便比较。

## 状态分层

```text
模型状态：config + vocab + 参数 E/P/Linear/LN
优化器状态：lr + beta + step + m/v
数据状态：语料摘要 + sampler RNG + batch_size
文件状态：schema + sha256 + 原子替换
```

每层状态有自己的职责。模型可以加载后直接推理；继续训练则必须同时拥有优化器和数据状态。把这些状态混在一个“神奇的 train_step”里，会使恢复行为无法解释。

## 为什么完整性摘要不是安全认证

SHA-256 能发现文件被截断或内容被意外修改，但不能证明文件来自可信发布者。v2 的目的只是教学实验的损坏检测。要支持发布和供应链验证，v5 还需要签名、来源和可信构建流程。

## 可靠性与性能的边界

v2 仍然不做大规模性能优化。AdamW 在 C++ 中有额外的状态读写，JSON 也会复制很多文本；这些取舍让状态可读、逻辑可检查。v3 才测量矩阵内核、跨语言复制和训练耗时，再决定怎样优化。

## v2 的错误处理原则

- 未知 schema 拒绝加载。
- 摘要不匹配拒绝加载。
- 词表长度、字符格式和模型词表大小不一致拒绝加载。
- 参数名称、shape 或优化器状态数量不一致拒绝加载。
- 训练语料摘要不同拒绝声称“精确恢复”。

每种拒绝都应该在短测试中出现一次。错误信息要指向用户可以修复的对象，而不是返回一个模糊的 `False`。
