# v1 设计说明：为什么这样写

## 设计判断

v1 的主要风险是把太多工程概念一次放进来。它因此刻意使用二维 Tensor、batch=1、单头、单 Block 和标准库 ctypes。每个选择都能在小输入上核对，学习者可以从一条中文文本追踪到一个损失数字。

## 数据路径和代码路径

```text
examples/train.py
→ training.py：采样 x/y、调用模型、调用优化器
→ model.py：Embedding、Block、输出投影
→ nn.py / functional.py：层与无状态函数
→ tensor.py：Python句柄包装
→ _backend.py：ctypes参数声明和错误转换
→ c_api.cpp：uint64句柄表
→ ops.cpp / tensor.cpp：真实数值和自动求导
```

这个方向把“模型结构”与“底层计算”分开。Python 里看到的 `x @ weight.T` 最终会落到 C++ 的 `gemm`；Python 不再写一份只用于演示的矩阵计算。

## 关键取舍

| 取舍 | 这样做的原因 | 后续代价 |
| --- | --- | --- |
| ctypes 而非 pybind11 | 不需要额外绑定包，能看见 ABI 与句柄 | Python API 更手工，数据复制与错误声明需要小心 |
| double 而非 float32 | 小例子更容易和手算、有限差分对照 | 内存和速度不代表真实训练硬件 |
| uint64 句柄表 | C ABI 不泄露 C++ 指针和容器布局 | 每次调用有查表开销，必须管理释放 |
| 每个Tensor二维 | shape、循环、反向公式直接 | 批处理和更高维模型需要后续设计 |
| 共享 E | 对应 GPT 常见 weight tying，也能学习多路径梯度 | 参数去重、加载和梯度累加都更复杂 |
| 绝对位置表 | 公式简单，适合第一层实现 | 窗口滑动和KV Cache需要重新定义位置语义 |
| SGD | 更新公式最直观 | 训练稳定性和收敛通常不如AdamW |

## 反向传播的核心边界

算子只负责自己的直接输入梯度。拓扑排序、路径合并、图生命周期由 `tensor.cpp` 负责。这样 `matmul` 不需要知道自己在 Attention 还是 MLP 中，也不需要为完整模型再写一份 backward。

反向前检查父节点 `version`，是为了阻止这样的错误：前向用了旧权值，优化器或测试先改了权值，再用旧图计算梯度。首版不提供任意原地写入，优先让错误早暴露。

## 为什么测试使用非均匀上游梯度

如果把 softmax 输出所有元素简单相加，结果恒为1，梯度可能恰好全为0；LayerNorm 在默认仿射参数下也有类似退化。测试使用 `[1, -2, 0.5]` 等固定权重构造标量 loss，才能真正覆盖链式求导。

## v1 之后的优化方向

先用 v1 建立数值基线，再在 v2 接入 AdamW、训练恢复、状态校验和更可靠的CLI。v3 才测矩阵循环、分块和跨语言开销。v4 处理缓存推理，v5 处理安装和发布。优化过程每次只改变一个因素，保留改前/改后结果。
