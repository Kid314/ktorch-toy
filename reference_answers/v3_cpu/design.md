# v3 整体设计说明

## 版本问题

v1 重点是“算对并学会文本”。v3 关注一个 AI Infra 常见问题：**算法公式相同，数据在内存中的访问顺序不同，执行时间可能不同。**

`gemm` 的数学式始终是：

```text
C[i,j] = Σ(k=0..K-1) A[i,k] * B[k,j]
```

变化只发生在循环嵌套顺序。`ijk` 直接表达公式；`ikj` 将 A 的一个元素复用到 C 的一整行。由于 row-major 连续布局，C 的内层 `j` 写入连续地址。

## 为什么暂时只做两种循环

分块、SIMD 和多线程会同时引入更多变量。v3 先固定 dtype、编译选项、矩阵尺寸和线程数，用一个可解释的变化建立测量习惯。每次修改都要先比较输出，再比较耗时。

## 计时边界

benchmark 应记录：

- 编译器与优化选项。
- A/B/C 的 shape 和 dtype。
- 预热次数与正式重复次数。
- 是否把 Python/ctypes、分配和数据复制算进时间。
- 输出差异的最大绝对误差。

本版脚本只把固定输入的模型前向矩阵乘法时间作为观察值，并且重复次数由参数控制。机器较慢时使用 `8×8`、三次重复即可。

## 优化方向

下一步可以在保持数学结果的前提下加入分块：把矩阵切成小 tile，控制工作集进入缓存；之后才考虑 SIMD 或线程。每次优化应保留旧策略作为基线，并用同一个输入做结果核对。

理论性能不能只看 FLOPs。还要考虑内存带宽、cache miss、Python/ctypes 开销和线程调度。v3 的计时结果只能说明当前机器、当前形状和当前编译条件。
